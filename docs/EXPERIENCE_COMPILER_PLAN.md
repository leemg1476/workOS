# 경험을 실행·검증 규칙으로 연결하는 개선 계획

기준: 2026-11-08 사용자 첨부 `goal-objective.md`의 네 구현 단위와 다섯 인수 기준. 기존 불변 이력·정확한 사실 범위·명시적 사용자 Apply를 보존한다. 기존42회/10회 연구는 재개하지 않는다.

## 요구사항과 완료 근거

|항목|구현할 결과|필요한 검증|
|---|---|---|
|PR1 정규화|상황·원인·대상 단계·행동·검사·금지 조건을 갖춘 규칙, 자유 교훈의 변환 후보|원문 불변, 불완전 후보 적용 거부|
|PR1 범위|입력에 묶인 사실과 계약/스키마/업무유형에 묶인 절차 분리|9월→10월 전이, 계약 버전 호환, 잘못된 단위/필드 변경 제외|
|PR1 관계|중복·충돌·파생·대체와 정정 이력|동시 활성 충돌 차단, 원자적 교체·롤백, 순환 차단|
|PR2 컴파일|규칙을 출력 필수항목·Decimal 계산·선행조건·근거 검사로 변환|무관 단계 제외, 실행하지 못한 규칙을 적용했다고 표시하지 않음|
|PR2 이행 추적|후보/선택/제외 이유/대상 단계/컴파일 결과/검사 결과를 Run에 고정|특정 Run에서 선택→산출물→검사 역추적, 스냅샷 변조 차단|
|PR3 비교|기초 기억 동일 고정, Challenger에만 후보 규칙 추가|같은 사례·원천·모델·예산, 누출/오래된 suite 차단, 퇴행·동률·실패 구분|
|PR3 활성화|평가 결과를 지식 Apply에 연결|실패/불충분 평가 적용 거부, 명시적 Apply/Reject/Rollback|
|PR3 의미 검사|주장과 입력/원문 연결, 구조 검사와 의미 판단 분리|틀린 수치·기간·방향·무근거 주장, 검토 미완료를 PASS로 위장하지 않음|
|PR4 유지보수|중복 근거 통합·정정·재검토/퇴역 제안, 지식별 효용/준수 관측 UI|지표 분모·N/A 명시, 전후 단순 점수차를 인과 효과로 표시하지 않음|
|3그룹 실험|무기억/현재 방식/개선 방식, 같은 모델·입력·도구 예산|학습과 보류 가구·기간·문서 분리, 오류·누락·재발·일반화·시도·토큰/비용 기록|
|사람 평가|순서를 가린 결과와 실제 사람 평가 입력 경로|미입력은 PENDING, Codex/모델 점수를 사람 평가로 사용하지 않음|

## 구현 순서

1. 정규화 계약·마이그레이션·유효 범위·관계와 회귀 검사를 먼저 구현한다.
2. 단계별 컴파일·검사·추적을 실제 공통 실행기에 연결한다.
3. 기존 고정 평가와 후보 지식을 연결하고 Apply 게이트·UI를 완성한다.
4. 유지보수·지표와 세 그룹의 보류 입력 검증을 실행한다.

모델을 새로 학습시키거나 외부 승인/메모리 서비스를 추가하지 않는다. P2 IAM/다중 사용자 전환은 저장소의 현재 단일 사용자 계약과 충돌하므로 이번 기억 루프에 섞지 않는다. 범용 도구/적응형 실행 확장도 핵심 루프 이후 우선순위로 유지하되, 지원 범위와 미지원 상태를 명시한다.

완료 표시는 위 각 항목의 실제 파일·실행 증거로 갱신한다. 인수 기준 다섯 개만 통과했다고 나머지 요구사항을 완료로 축소하지 않는다.
