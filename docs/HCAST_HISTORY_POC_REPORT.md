# 사람 기준시간과 업무 기록 재사용 PoC: HCAST 문서 조사

기준일: 2026-11-01. **결론: 과거 Work 결과와 독립 채점 기록을 쌓아 다음 실행에 전달하는 실험은 수행했지만, 기록 축적으로 더 잘 수행한다는 증거는 얻지 못했다. 사람의 업무시간 절감도 입증하지 못했다.**

## 1. 질문에 대한 직접적인 답

현재 Work OS 일반 텍스트 업무는 같은 Task의 이력·피드백·실패 기록을 자동으로 검색해 모델에 주입하지 않는다. `backend/app/workloads/text_workflow.py`는 해당 Task의 목표, 현재 단계, 고정된 입력과 같은 Run의 선행 단계 결과를 모델에 전달한다. 별도 업무 연결이 설정되면 사람이 채택한 선행 업무의 산출물이 들어갈 수 있다. VOC 데모의 이전 보고서 연결은 별도 업무 전용 로직이다.

**이번 PoC에서만** 외부 실험 코드가 별도 PostgreSQL의 이전 Work·Artifact와 공식 정답 채점 기록을 읽고, 다음 작업의 입력으로 직접 조립했다. 이력 테이블과 선택 로직은 실험 전용이며, 현재 제품의 자동 이력 검색이나 자동 개선 기능이 아니다. 데이터가 입력에 들어갔다고 해서 모델이 가중치를 학습하거나 그 내용을 올바르게 활용하는 것도 아니다.

## 2. 사람 시간의 실제 출처와 적용 범위

[METR HCAST 논문](https://metr.org/hcast.pdf)은 사람이 실제로 도전한 563건의 기준 측정을 설명한다. 성공한 사람의 시간으로 과제 기준시간을 산출하며, 성공 기준 기록이 없는 경우에는 예측치를 쓰기도 한다. 별도의 [측정 분석 논문 표](https://openreview.net/pdf?id=CGNJL6CeV0)는 특정 과제 `local_research_tex/ar_report`의 **사람 기준시간을 24분**으로 표시한다. 이것은 개인당 인건비나 모든 작업의 평균이 아니다.

이 과제는 로컬 논문 모음에서 특정 질문의 답을 찾는 연구용 과제다. HCAST 저자들이 만든 벤치마크로, 특정 회사의 실제 업무 티켓이라는 뜻은 아니다. 원본 과제와 채점기는 [METR 공개 저장소의 고정 커밋](https://github.com/METR/hcast-public/tree/03438239d200fb3e89a5ddfc62ab4d23cc1866fb)에 있다. 원 공개 저장소는 평가 데이터의 학습 코퍼스 유입 방지를 요청한다. 본 실험은 모델 호출 `store=False`, 모델 미세조정 없음이며, 저장소에 원본 논문 전체를 복제하지 않았다.

우리 실행은 원본 전체 환경을 사람과 동일하게 재현하지 않았다. PDF/HTML 및 공개 TeX·참고문헌의 **텍스트만 추출**해 1,200자씩 겹쳐 나누고, TF-IDF 상위 4개 발췌만 텍스트 실행기에 전달했다. 원본의 78개 파일 전체, 이미지, 파일 탐색 도구와 동일한 환경이 아니다. 따라서 **24분과 이 실험의 모델 호출 시간은 직접 비교하거나 절감률로 환산할 수 없다.**

추가로 실제 기업의 헬프데스크 티켓을 담은 [Mendeley Help Desk Tickets](https://data.mendeley.com/datasets/btm76zndnt/1)도 확인했다. 이 데이터의 시간은 티켓이 특정 상태에 있었던 경과시간이어서 사람이 실제로 집중해 일한 시간으로 확인되지 않았다. 요청하신 인력시간 근거로 오인할 수 있어 이번 성과 계산에 사용하지 않았다.

## 3. 방법과 정답 오염 방지

- 대상: HCAST 공개 문서 조사 과제. 초기 5개 과제로 문제를 파악하고, 이어 이전에 실행하지 않은 5개 변형, 다시 이전에 실행하지 않은 4개 변형을 사용했다. **후속 9개는 공개 코드의 과제 변형**이며, 모두 METR 공개 평가 스위트에 포함된 것은 아니다. 공개 자료이므로 모델의 사전학습 노출 여부도 알 수 없다.
- 실제 실행: 같은 텍스트 업무를 등록하고 `gpt-6-luna`를 Work OS WorkItem → queue → worker → Artifact 경로에서 LIVE 호출했다. 평가 업무는 격리 DB `hcast_history_poc`에서 수행했다. 원본의 공식 `TaskFamily.score`를 호출해 독립적으로 채점했다.
- 이력: 실제 저장된 이전 Work의 질문·출력·공식 채점과 기준 답안을 참조했다. 실행 중인 질문과 미래 질문의 정답은 이력에 넣지 않는다. 각 문제의 대조군과 이력군을 모두 마친 뒤에만 그 문제의 대조군 결과를 기록으로 추가했다. 과거 기록은 Artifact 해시를 다시 확인하고 실험 전용 append-only 테이블에 보관했다.
- 중요한 한계: 과거 기준 답안은 공개 벤치마크의 정답을 재생한 **모의 피드백**이다. 실제 고객의 자연어 피드백이나 사람이 우리 실행 결과를 검토한 기록이 아니다. 구조상 사람이 주는 피드백을 어떻게 전달할지 실험한 것이며, 자율적으로 정답을 알아낸 학습이 아니다.
- 모델 입력: 각 쌍의 공통 질문과 발췌는 같다. 실험 ①은 이력만 덧붙이고, 실험 ②는 양쪽에 같은 이력을 주고 후보의 단계 지시만 다르게 했다. 각 조건은 1회 호출했으며 무작위화·반복 시행은 하지 않았다. 정답이 담긴 원본 채점기는 모델 프롬프트에 넣지 않았다.
- HCAST 채점은 정답만 정확히 출력해야 한다. 현재 Work OS 시스템 지시는 한국어 응답을 요구하므로, 내용상 답에 가까워도 한국어 설명이나 단위를 덧붙이면 공식 점수가 0이다. 시스템 지시와 과제 출력 형식의 충돌을 별도로 기록했다.

## 4. 실제 결과

### 초기 5개: 이력 수집과 실패 분석

9회 실행 중 초기 질문 `atari_epochs`는 `3회`라는 취지의 답을 냈으나 정답만 출력하지 않아 공식 채점에서 실패했다. `which_does_worse`의 대조군은 정답을 맞혀 검증된 과거 기록 1건이 되었다. 다음 `33b_better_than_65b`, `more_bias`의 응답도 정답에 가까운 한국어 설명이 추가되어 공식 채점에서 실패했다.

첫 실험의 유사도 기반 검색은 후속 질문들에 대해 이전 기록과의 유사도가 낮아 기록을 0건 선택했다. 따라서 **기록이 실제로 전달됐을 때의 효과를 이 초기 구간에서 입증할 수 없다.**

사람 24분 기준이 있는 `ar_report`는 원본의 공식 정답이 `4`다. 우리 초기 대조군과 이력군은 각각 **5.454초, 5.906초 후 Run 실패**로 결과물이 없었다. 추가로 과거 채점 기록 4건과 수정 후보 지시를 넣어 같은 문제를 재시도했으나, **5.547초에 `7`을 답해 공식 채점 0점**이었다. 마지막 재시도는 이미 본 과제를 사후 재실행한 것이므로 독립 평가가 아니다. 실패한 5초대 실행과 사람이 문제를 맞힌 24분을 비교해 ‘빠르다’고 하면 안 된다.

### 실험 ①: 실제 과거 기록 제공 여부 — 미사용 5개 변형

초기 실행의 Artifact가 있는 4건에서 출발해 각 쌍 종료 후 결과를 추가했다. 각각의 이력군에는 이전 4건을 넣었고, 이력 저장 수는 작업이 진행되면서 4→9건으로 늘었다.

| 과제 | 이력 없음 | 이전 기록 제공 |
|---|---:|---:|
| `author_letter` | 1 | 1 |
| `sentence_letter_theodore` | 1 | 1 |
| `td_year_adam` | 0 | 0 |
| `atari_parameters_amy` | 0 | 0 — Run 실패 |
| `task_not_moving_amy` | 0 | 0 — Run 실패 |
| **합계** | **2/5** | **2/5** |

기록 제공은 이 다섯 사례에서 정답 수를 늘리지 못했다. 두 이력군 Run은 실패했다. 출력 형식뿐 아니라 정답이 포함된 문서 발췌가 검색되지 않은 경우가 있었고, 과거 작업 기록을 더 넣는 것만으로 이를 자동 수정하지 못했다.

### 실험 ②: 실패 피드백을 바탕으로 지시 변경 — 별도 미사용 4개 변형

초기 실행에서 관찰한 **정답 외 설명으로 채점 실패** 문제를 바탕으로, 후보 지시에 답만 출력하는 형식 예시를 추가했다. 같은 4개의 선행 기록·질문·발췌를 양쪽에 제공하고, 두 작업 정의는 해당 단계의 지시만 다르게 했다. 후보는 운영 Task에 자동 적용하지 않았다.

| 과제 | 기존 지시 | 후보 지시 |
|---|---:|---:|
| `section_letter_theodore` | 1 | 1 |
| `clearer_section_letter_theodore` | 1 | 1 |
| `td_month` | 0 | 0 |
| `trpo` | 0 — Run 실패 | 0 — Run 실패 |
| **합계** | **2/4** | **2/4** |

형식 지시를 바꾸었지만 **독립된 네 과제에서 정확도 개선은 확인되지 않았다.** 네 개라는 매우 작은 표본, 공개 벤치마크, 제한된 발췌와 단발성 호출 때문에 우열을 일반화할 수 없다. 원인 분석도 가설이며, LLM의 변동성과 호출 순서가 결과에 영향을 줄 수 있다.

## 5. 실행 이력과 증거

총 28회 LIVE Work 실행 중 Run 성공 22회, 실패 6회. 성공했다고 해서 정답이거나 최종 승인된 것은 아니다. Work OS 텍스트 구조 검증은 내용의 사실성을 검증하지 않으며 성공 결과는 사람이 검토할 `WAITING_APPROVAL`에 남겼다. 실제 사람의 승인을 위조하지 않았다. Work 이력 12건을 참조하는 실험용 피드백 레코드가 쌓였고, 그중 공식 채점 통과는 5건이다. 타임스탬프 순서가 아니라 위에서 명시한 실험 순서로 연결했다.

22개 성공 응답의 기록된 토큰은 입력 41,773개, 출력 3,334개다. 실패 호출의 토큰 사용량은 기록되지 않아 전체 사용량의 확정값이 아니다. 28개 Work 요청 처리시간 합은 98,958ms이나 입력 검색, 사람 검토, 실패 복구, 운영 대기시간 전체를 포함하지 않는다. API 청구 금액과 사람의 검토 시간은 측정하지 않았다.

- [초기 5개 과제 및 24분 과제 기록](evidence/hcast_history/run.json): SHA-256 `7f4319973052dc251ad011d26ffa40674f8f585a3703e9dfc4b84183371a2a69`.
- [미사용 5개 과제의 이력 유무 비교](evidence/hcast_history/followup.json): SHA-256 `0cb133670937c3dc3492159387226fb0676e88e74b698b56e74260d51d39ec7b`.
- [미사용 4개 과제의 후보 지시 비교](evidence/hcast_history/candidate.json): SHA-256 `b3c824201488828c0edbf3a535e43d49c35475769d572366191638ea53443cdf`.
- [24분 과제의 사후 재시도](evidence/hcast_history/recovery.json): SHA-256 `c35dbd2ff11c35b5e3e02810d4989582987725bca117a5462e7df479d57be117`.
- [실험 코드](../experiments/hcast_history/)와 [검증 코드](../experiments/hcast_history/verify.py): 공식 채점, 과거 기록만 사용했는지, 동일 발췌, 입력·Artifact 해시, 결과를 재확인한다. 독립 재검증 결과 **28 Run, 성공 22/실패 6, 이력 유무 2/5 대 2/5, 후보 2/4 대 2/4**. 실험용 이력 UPDATE는 append-only 트리거로 거부됨을 확인했다.

증거 파일은 콘텐츠 해시와 응답 ID를 보존하지만 외부 서명이나 제공자 측 재조회로 진위를 입증한 것은 아니다. 실패 호출 토큰을 모르는 것, 모델의 사전학습 오염 가능성, 부분 발췌, 원본 정답의 완전성, 단일 시도와 작은 표본이 남는다.

## 6. 지속 개선을 위해 필요한 제품 구조

1. 같은 Task에 연결된 과거 Work·Run·Artifact·사람 피드백·실패 원인을 조회 가능한 형태로 연결하고, 어떤 기록이 다음 Run에 반영될지 명시한다. 외부 모델로 이전 내용이 전송되는 경우 사용자에게 알리고 선택하도록 해야 한다.
2. 채택된 근거와 사람의 평가, 미검증 추정, 실패를 구분하고 출처·버전·해시를 고정한다. 현재 작업이나 평가용 비공개 정답이 과거 이력에 섞이지 않게 차단한다.
3. 검색된 기록을 무작정 추가하는 대신 해당 업무와 관련된 내용과 실제 개선 후보에 연결한다. 입력 길이·오래된 내용·지시 충돌과 유해한 데이터 명령을 통제한다.
4. 기존 방법과 후보를 같은 고정 평가 입력에 여러 번 실행하고, 품질·중요 오류·시간·비용과 회귀를 비교한다. 평가 통과와 명시적 사용자 적용을 분리하고 거부·복구를 지원한다.
5. 실제 사람이 같은 업무를 수행한 시간과 Work OS 사용 시 준비·검토·수정·예외 처리 시간을 측정한다. 현재 HCAST 사례와 같은 제한된 벤치마크 점수만으로 사람 시간 절감이나 현업 성과를 단정하지 않는다.
