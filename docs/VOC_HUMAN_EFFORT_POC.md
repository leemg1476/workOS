# 사람의 업무시간과 결과 비교 PoC

## 목적과 현재 결론

Work OS가 사람의 개입을 줄이면서 업무의 결과를 개선하는지 측정할 수 있는지 확인한다. 현재 구현은 **가상 고객 문의 분류**를 이용한 측정 경로다. 실제 사람이 1시간을 사용했다는 기록도, 다음 주에 시간이 단축되거나 정확도가 개선됐다는 관찰도 없다. 실제 성과는 아직 입증되지 않았다.

## 사용 순서

1. 업무 현황의 **사람의 시간과 결과를 비교합니다**에서 가상 1주차 문의 24건을 직접 분류한다. 준비 시간부터 포함해 시간을 측정·보정하고 기준선을 저장한다. 시스템은 1시간을 자동으로 넣지 않는다.
2. **같은 입력 + Work OS**에서 타이머를 사용하고 실행을 요청한다. 기존 TASK-003의 검증된 결과를 확인하고 필요한 항목을 수정한다. 수정한 항목은 확인 표시가 필요하다. 검토와 시간을 저장하면 초안 및 검토 후의 합성 정답 일치 수, 확인·수정 수와 자기 기록 시간을 비교한다.
3. 원하는 경우 **누락 피드백으로 후보 만들기**를 누른 뒤 동일한 합성 고정 사례와 별도 회귀 사례로 기존·후보를 평가한다. 통과하더라도 사람이 명시적으로 적용해야 하며 복구할 수 있다. 후보는 사전 준비된 분류 규칙으로 사람의 수정에서 자동 생성되거나 학습되지 않는다. 같은 입력을 다시 실행해 사례별 개선·퇴행을 확인한다.
4. 기준선 저장 이후 **주간 예약 켜기**를 선택하면 최소 7일이 지난 뒤 같은 가상 2주차 입력을 매주 실행한다. 예약을 켜지 않으면 자동 실행하지 않는다. 예약은 중지·재개할 수 있고 사람의 검토를 대신하지 않는다. 다음 주 입력을 수동 실행할 수도 있다.
5. 2주차 결과를 확인·수정하고 시간을 기록한다. 기준선 대비 7일이 지나기 전 실행·저장한 것은 당일 리허설이다. 기간이 지난 기록도 그 자체만으로 실제 업무 성과가 되지는 않는다.

## 비교의 의미와 한계

- 데이터는 사전에 만든 합성 문의와 라벨이다. TASK-003 분류는 MOCK 결정론적 규칙이며 실제 고객 데이터나 LLM 분류가 아니다.
- 시간과 확인 여부는 사용자의 자기 기록이다. 동일인 여부, 실제 활동, 정답 사전 노출 및 순서·학습 효과를 검증하지 않는다. 타이머는 탭을 벗어난 시간도 포함하고 사람이 보정할 수 있다.
- 같은 1주차 입력에서 방법을 바꾸기 전후의 초안 정답 수와 사례별 개선·퇴행을 비교할 수 있다. 이 역시 공개된 합성 정답에 대한 결과다. 2주차는 다른 입력이므로 점수 차이만으로 방법 변경의 인과 효과를 판단할 수 없다.
- 2주차 자료는 주마다 실제로 새로 수집되는 자료가 아니라 동일한 고정 합성 자료다. 시간 단축, 더 적은 검토 또는 더 높은 실제 정확도는 실제 사람이 실제 업무를 반복 측정하고 독립 기준으로 평가해야 주장할 수 있다.

## 증거와 안전장치

측정은 입력·정답·요청의 해시, 사용자 답변, 확인·수정 기록, 시간, 검증된 Run·Artifact·Evidence 및 방법·검증기 버전을 함께 저장한다. 기준선 이전에 시작한 Run, 다른 주차 입력, 변경된 증거와 확인 표시 없는 답변 수정은 거부한다. 동일 요청 재전송은 중복 기록을 만들지 않는다. 예약 입력도 해시로 고정하고 기준선·예정 시각을 남긴다. 측정·예약 증거가 존재하면 해당 데이터베이스 변경을 되돌릴 수 없다.

## 실제 증명에 필요한 다음 단계

실제 사용자가 수행하는 반복 업무와 자료 수집 범위에 동의하고, 독립적으로 검증할 기대 결과와 평가 사례를 먼저 정한다. 동일한 업무 범위에서 사람만 수행한 기준 시간과 품질을 기록하고, 이후 실제 신규 입력의 준비·검토·수정 시간을 모두 포함해 같은 기준으로 평가한다. 결과는 측정값, 오차와 사례별 오류를 함께 제시하며, 표본이 부족하면 성과를 단정하지 않는다.
